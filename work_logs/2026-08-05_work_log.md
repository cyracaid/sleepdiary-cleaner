### 二、Figure 改造 —— 两大图集

#### 图集 1：Pipeline Overview（流程图）

**当前：** Figure 1 用 `geom_tile` 固定坐标 + 手画箭头，视觉上不是真正的流程图，分支箭头对不齐。

**目标：** 从左到右的标准流程图，审稿人无需看代码即可理解整条管线。

**必需类别（展示数量和占原始总数的百分比）：**

| 类别 | 含义 | 颜色 |
|------|------|:--:|
| Raw records | 原始输入总数 | — |
| Auto-detected errors removed | 自动检测出的错误，移除 | 🔴 红 |
| Algorithmically corrected | 算法自动修复（Step 4 normalize + 自动逻辑） | 🟠 橙 |
| Manually corrected | 人工通过 manual CSV 修正（Step 6） | 🔵 蓝 |
| Reviewed, unchanged | 生成 review CSV 后人工看过但决定不改 | 🩶 灰 |
| No issues / clean | 从头到尾没被标记 | 🟢 绿 |
| Final analysis dataset | 最终进入分析的记录数 | — |

> **区分要点：**
> - "Auto-detected errors removed" = 数据被检测为不可修复，从分析中移除
> - "Algorithmically corrected" = 算法自动修复了值（如 AM/PM 翻转、时间对调）
> - "Manually corrected" = 人工在 manual CSV 里写入修正值
> - "Reviewed, unchanged" = 生成了 review file，人看了，决定不改

**实现方式：** DiagrammeR 优先；备选 ggplot2 精确坐标布局。

### 五、输出列名重整（本周最重要任务之一）

**当前问题：** 清洗后的 dataframe 有上百列，大多数是中间过程列，研究者拿到数据后完全不知道哪些是"最终结论"、哪些是"中间过程"。

**目标：** 最终输出（CSV/RDS）仅保留有意义、可复用的列，其余保留但不暴露为主输出。

**需要保留的核心列：**

| 类别 | 列名模式 | 用途 |
|------|---------|------|
| 原始时间 | `*_am_hhmm_ampm` | 参与者原始输入（AM/PM 格式参考） |
| 解析后时间 | `time_bed_*/time_sleep_*/time_awake_*/time_getup_*` | 解析后的 POSIXct 时间 |
| 时长 mincalc | `*_mincalc` | 统一为分钟的时长（SOL/WASO/nap/exercise） |
| 校正后时间 | `*_corrected` | 经过 normalize + 人工修正后的最终时间 |
| 衍生差异 | `self_diffcalc_*` | Step 7 计算的睡眠指标（TST/SOL/SE/WASO） |
| 公共契约列 | `sleep_efficiency_pct / sol_h / waso_h / sleep_duration_h` | Step 7 产出，供后续分析使用 |
| 修正标记 | **需新建：** `has_correction` (TRUE/FALSE) | 是否有任何修正（算法或人工） |
| 修正类型 | **需新建：** `correction_type` | "none" / "algorithmic" / "manual" / "both" |
| 标记严重度 | `flag_severity` | Clean / Minor / Major |

**原则：**
- **不删列**：原始过程列保留但不做为主输出，单独保存为"完整中间结果"
- **输出双文件**：
  - `cleaned_data_final.csv/rds` — 仅包含核心分析列（20-30 列）
  - `cleaned_data_full.csv/rds` — 完整列集（供追溯/调试）
- 在 `SCHEMA.md` 中写清楚每列的来源和作用

## 八、NULL 问题专项排查（2026-08-05 执行）

对全部 9 个管线脚本进行 NULL 审计，发现 **13 项**，其中需修 5 项：

### 需要修

| # | 文件 | 行 | 问题 | 严重度 |
|---|------|----|------|:--:|
| 1 | `sleep_visualization.R` | 115 | `sleep_duration_h` 为 NA 时被 `flag_duration_extreme` 标为 "Normal range" | 🔴 输出错误 |
| 2 | `calculate_sleep_time_end.R` | 158 | TST / TIB 除零导致 `sleepefficiency_percent = Inf`，扭曲图轴 | 🔴 输出错误 |
| 3 | `sleep_visualization.R` | 463 | `data_category` 为 `NA_character_` 静默归为 "Other"（正常流程不触发，缺防御） | 🟡 风险 |
| 4 | `error_unusual_sleep_time_corrections.R` | 1089 | `ensure_marking_columns()` 裸 NA 补 `data_category`，类型不一致 | 🟡 风险 |
| 5 | `sleep_visualization.R` | 930 | Figure 8 的 `exists()` 检查缺 `is.data.frame()` 守卫 | 🟡 风险 |

> **Bug 1 白话解释：** 给每条记录打标签——睡不到 3 小时标"太短"，超过 12 小时标"太长"，其他标"正常"。但遇到空白的记录（人家根本没填），代码拿着空白问"小于 3 吗？"答不上来，问"大于 12 吗？"也答不上来。两个都答不上，代码就说"那算正常吧"——空白的被标成了正常。这是错的。修完后代码先看一眼"这是空的吗？"——是的——直接标 "Missing"，不往下问了。
>
> **Bug 2 白话解释：** 计算睡眠效率 = 总睡眠时间 ÷ 尝试入睡时间。有些记录尝试入睡时间是 0 分钟（清醒时间和睡着时间一样），120 ÷ 0 = Inf（无穷大）。无穷大跑进 ggplot 后坐标轴被无限拉大，图直接废了。修完后先看分母——如果是 0 或更小，直接设 NA，不做除法。

### 低优先级（不改）

| # | 问题 | 原因 |
|---|------|------|
| `checkforerrors_processed <- data.frame()` 空 df | 下游有 `nrow > 0` 守卫 |
| `raw_csv_data <- NULL` 文件缺失 | `is.null()` 守卫正确处理 |
| `find_duration_columns()` 返回 NULL | 所有调用者正确守卫 |
| `needs_manual_check = NA` 裸逻辑型 | 极低风险 |

### 风险结论

当前管线正常运行时 **不触发** 上述错误（Step 4 → Step 6 → Step 9 依序执行情况下）。风险主要在：
- 未来有人跳过 Step 6
- 数据中出现异常除零
- 某人绕开 `recalculate_and_mark_errors()` 直接调可视化
