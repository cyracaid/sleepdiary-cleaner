# 2026-08-13 Work Log — sleep_awake_swap_3h guard (Channel B follow-up)

## Context

Channel B redundant-channel validation (2026-08-12) found `sleep_awake_swap_3h`
worsens SOL on real data: 7/10 corrected rows moved farther from self-reported
SOL (p=0.036), with 6/7 of those violations caught by the pipeline's downstream
temporal-order check and 1 (pid 6490 day 12) silently delivered.

## Fix (shipped in working tree, commit 606a0e0)

`normalize_sleep_time_sequence.R` Section 5.2 adds a guard to the swap condition:

- BEFORE: `if (sleep > awake && abs(sleep_awake_diff) < 3)` → swap
- AFTER:  `if (sleep > awake && abs(sleep_awake_diff) < 3 && bed <= awake)` → swap

Mechanism: swapping when old `awake` is EARLIER than `bed` puts the new "sleep"
time before bed, so the corrected `bed→sleep` gap lies about as far (or farther)
from self-reported SOL as the raw gap. Guarded rows are left uncorrected; the
downstream temporal-order check flags them for human review (the path that
already caught 6/7 worsened cases).

Applied to BOTH copies (root + inst/scripts/), md5-identical.

## Tests

Added 2 unit tests in tests/testthat/test-normalize.R:

1. swap refused when old awake < bed (not corrected, times unchanged)
2. swap allowed when old awake >= bed (order restored bed <= sleep <= awake)
