Optimize the sleep diary EMA data processing R pipeline to reduce manual inspection workload by automatically filtering out non-actionable data quality flags.

## Change 1: Exclude Exercise & Nap Interval Format Checks

### File

`checkforerrors_processing.R`

### Motivation

Format checks for `exercisetoday*` (L/Moderate/Vigorous/Strength) and `duration_totalmin_napstoday_PM` generated ~81% of UNUSUAL_VALUE noise (~4,691 non-NA records). These variables are unrelated to core sleep metrics (SOL, TST, SE, WASO), so their format errors are not actionable.

### Modification

Added exclude filters in Part A (`needs_review_flag` setting) and Part 3 (`yellow_flags`/`red_flags` counting) to skip check columns matching `exercisetoday` and `duration_totalmin_napstoday_PM`.

```r
# Part A — exclude from iteration loop
exclude_irrelevant <- grepl("exercisetoday|duration_totalmin_napstoday_PM", check_cols[i])
if (!exclude_irrelevant) { ... }

# Part 3 — exclude from severity classification
if (!grepl("exercisetoday|duration_totalmin_napstoday_PM", tolower(names(ema_data)[i]))) { ... }
```

### Effect

Flags persist in original data (preserving audit trail) but no longer trigger review.

| Metric | Before | After |
|---|---|---|
| UNUSUAL_VALUE | 2,628 | 8 |
| Total non-CLEAN | 3,399 | 759 |
| checkforerrors_df | 4,069 | 1,449 |

## Change 2: Clear Timestamp checkforerrors After Normalization

### File

`normalize_sleep_time_sequence.R`

### Motivation

`process_timestamp()` in `process_timestamp_emadatarelease_cyra.R` writes human-readable parse-error descriptions (e.g., "both time and am/pm missing", "time missing", "unparseable format") to `*_checkforerrors` columns when the raw input string has format issues. These are **parse-time warnings**, not data validity errors.

The subsequent auto-correction logic in `normalize_sleep_time_sequence.R` (±12h adjustments, order swaps) already extracts valid POSIXct time values from raw strings even when the original format was problematic. `normalize_sleep_time_sequence.R` creates `*_corrected` columns but never clears the stale `*_checkforerrors` entries from `process_timestamp.R`.

### Modification

After all automatic corrections, clear the four timestamp check columns:

```r
checkforerrors_pairs <- list(
  list(raw = "time_bed_am_checkforerrors", corrected = "time_bed_corrected"),
  list(raw = "time_sleep_am_checkforerrors", corrected = "time_sleep_corrected"),
  list(raw = "time_awake_am_checkforerrors", corrected = "time_awake_corrected"),
  list(raw = "time_getup_am_checkforerrors", corrected = "time_getup_corrected")
)

for (pair in checkforerrors_pairs) {
  if (pair$raw %in% names(cleaned_data)) {
    valid_mask <- !is.na(cleaned_data[[pair$corrected]])
    cleaned_data[[pair$raw]][valid_mask] <- NA_character_
  }
}
```

Key rationale: use `!is.na(time_*_corrected)` rather than `corrected == TRUE`. The `corrected` flag only indicates that `normalize_sleep_time_sequence.R` made an active adjustment (±12h shift or swap). Many records with valid `*_corrected` values have `corrected == FALSE` because the original time sequence was already valid — the system successfully extracted a time despite messy raw input formatting.

### Effect

| Metric | Before | After |
|---|---|---|
| SERIOUS_RED_LINE | 751 (post-Fix1) | **0** |
| Total non-CLEAN | 759 | 61 (53 manual + 8 UNUSUAL_VALUE) |
| checkforerrors_df | 1,449 | 1,013 |
| Timestamp *_checkforerrors non-NA | ~771 | **0** |

## Change 3: Intelligent RED/YELLOW Severity Classification + New BEHAVIORAL Category

### File

`checkforerrors_processing.R`

### Motivation

The original classification strategy applied YELLOW uniformly to all non-RED columns, causing:
- Substance use threshold flags (caffeine >4 cups, alcohol >3 drinks) were classified as UNUSUAL_VALUE, but they reflect participant lifestyle choices, not data quality issues
- Substance use timestamp format errors (e.g., missing AM/PM on caffeine consumption time) were marked YELLOW, but these are contextual variables that don't affect core sleep metrics

### Modification (Two Rounds)

**Round 1** — Excluded the following columns from both Part A and Part 3:
- `caffeinetoday_PM_checkforerrors` / `alcoholtoday_PM_checkforerrors`
- `nicotine_amount_pm_checkforerrors` / `cannabis_amount_pm_checkforerrors`

These are substance-use timestamp format-error columns — contextual variables not involved in sleep quality computation.

**Round 2** — Redesigned the severity mapping into a three-tier system:

```r
# Tier 1 — RED: Data integrity errors (affects core sleep metrics)
#   Sleep timestamp format errors (safety net; should be 0 after normalize)
#   SOL interval format errors (core metric)

# Tier 2 — YELLOW: Minor data quality concerns
#   WASO interval format errors (important but lower severity than SOL)

# Tier 3 — BEHAVIORAL: Lifestyle/substance flags (not data quality)
#   caffeine_value_checkforerrors (caffeine >4 cup threshold)
#   alcohol_value_checkforerrors (alcohol >3 drink threshold)
#   nicotine_value_checkforerrors
#   cannabis_value_checkforerrors
```

Added a `behavioral_flags` counter. Updated `final_status` logic:

```r
raw_severity[red_flags > 0] <- "SERIOUS_RED_LINE"
raw_severity[red_flags == 0 & yellow_flags > 0] <- "UNUSUAL_VALUE"
raw_severity[red_flags == 0 & yellow_flags == 0 & behavioral_flags > 0] <- "BEHAVIORAL"
raw_severity[red_flags == 0 & yellow_flags == 0 & behavioral_flags == 0] <- "CLEAN"
```

### Effect

| Category | Before | After |
|---|---|---|
| SERIOUS_RED_LINE | 0 (eliminated by Change 2) | **0** |
| UNUSUAL_VALUE | 8 | **0** |
| BEHAVIORAL (new) | — | **8** |
| CLEAN | 13,929 | **13,929** |
| CLEAN (Manually Fixed) | 53 | **53** |

## Key Decisions Log

| Decision | Rationale |
|---|---|
| Dual exclusion (Part A + Part 3) instead of deleting columns | Preserve audit trail: flags exist in raw data but don't trigger review |
| Clear checkforerrors based on `!is.na(*_corrected)` not `corrected == TRUE` | `corrected == TRUE` only indicates active adjustment (±12h/swap). Many records have valid corrected values despite messy raw input, with `corrected == FALSE` because the sequence was already valid |
| Substance value flags → BEHAVIORAL, not excluded entirely | Still visible in classification output for researcher reference, but won't trigger review |
| Substance timestamp columns excluded from entire pipeline | Contextual variables (time of coffee consumption, etc.), don't affect SOL/TST/SE/WASO |
| Keep 4 timestamp columns as RED safety net | Currently 0 after normalize clearing, but if normalize logic changes in the future, RED classification provides a fallback |
| SOL interval → RED, WASO interval → YELLOW | SOL is a core sleep metric (sleep onset latency); WASO is important but secondary in severity |
