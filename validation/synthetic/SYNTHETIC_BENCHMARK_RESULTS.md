# Synthetic Benchmark — Calibrated Injected-Error Validation

Status: first pass complete (2026-08-12). Directly produced the two bug fixes
shipped in v1.4.1. Full recall/specificity/PPV-curve treatment, cluster
bootstrap CIs, and multiverse analysis (see `benchmark-design.md` in the
project docs) are still pending — this covers FCR (false-alteration) testing
and a first per-category detection/recall pass, not the complete design.

Scripts and data live in `validation/synthetic/` (gitignored `.rds`/`.csv`
outputs are regenerated by running the scripts; commit only tracks the code,
the error taxonomy, and the aggregate result tables below).

## What's here

- `generate_clean_data.R` — parameterized clean-data generator. `mode=pure`
  (near-zero-variance, for the false-correction test) vs `mode=plausible`
  (population-realistic: healthy_adult, insomnia_like, short_sleeper,
  shift_like presets). Every row is monotonic and format-valid by
  construction.
- `error_catalog.yaml` — 12-category error taxonomy, each tagged with
  provenance (observed / literature / blind_spot) so the injected
  distribution isn't circularly calibrated off the pipeline's own detected
  errors.
- `inject_errors.R` — participant-clustered injector (not IID), enriches
  each category to a fixed target count, logs one ground-truth row per
  injected error (original value, corrupted value, true value, mechanism).
- `evaluate_fcr.R` — false-alteration-rate evaluator (structurally-pure and
  population-stratified inputs).
- `evaluate_detection.R` — per-category detection/recall evaluator, compares
  the pipeline's derived values directly against `ground_truth.csv`'s
  `true_value` column.
- `results/` — aggregate result tables (`fcr_pure_n10000_result.csv`,
  `enrichment_detection_outcomes_v3.csv`, `detection_outcomes_v4.csv`).

## Results

### FCR test A — structurally pure, n=10,000

**FAR_alter = 0/10,000.** Rule-of-three 95% upper bound ≈ 0.03%. Verified
against the pipeline's own parsed-truth columns (not raw display strings,
which would have falsely counted 10,000/10,000 "alterations" that were pure
reformatting).

### Test B — physiologically-realistic per population, n=3,000 × 4

Zero value alterations confirmed on all 12,000 rows. Flag rate by
population:

| Population | n | Error | Unusual | DURATION_ISSUE | Flag rate |
|---|---|---|---|---|---|
| healthy_adult | 3000 | 0 | 0 | 0 | 0.0% |
| short_sleeper | 3000 | 0 | 0 | 0 | 0.0% |
| shift_like | 3000 | 9 | 1 | 0 | 0.3% |
| insomnia_like | 3000 | 0 | 6 | 224 | 7.7% |

Quantifies `THRESHOLDS.md`'s documented caveat that default thresholds are
tuned on a healthy young-adult sample: a legitimately-long-SOL/WASO
population gets flagged at roughly 26x the rate of the tuning population,
on real, unmanipulated (synthetic-clean) data. Zero of these flags
corresponded to a silently-altered value. (Note: the per-population
FAR_alter split still needs an NA-vs-altered fix in the evaluator before an
exact number is quoted per population — the pipeline's own "Corrected: +0"
report is the trustworthy figure here.)

**Headline finding:** field misentry (a clock time typed into the SOL/WASO
duration field — the pattern behind the real pid-1036 case referenced in
`error_catalog.yaml`'s design rationale) doesn't just evade detection, it
gets silently "corrected" to a wrong value 95.8–96.0% of the time with no
flag. This is what `checkforerrors_processing.R`'s Part A4 patch (shipped
in v1.4.1) fixes.

### Patch verification (post-fix, same harness)

| | Pre-patch | Post-patch |
|---|---|---|
| field_misentry_sol silent misrepair | 383/400 (95.8%) | **14/400 (3.5%)** |
| field_misentry_sol overall caught | 17/400 (4.2%) | **386/400 (96.5%)** |
| field_misentry_waso silent misrepair | 384/400 (96.0%) | **0/400 (0%)** |
| field_misentry_waso overall caught | 16/400 (4.0%) | **400/400 (100%)** |
| FCR n=10,000 false positives from the new rule | n/a | 0/10,000 |

WASO closed completely. SOL's residual 3.5% are "01:XX"-shaped clock times
that produce no `_correctionsmade` text at all — disclosed as a structural
limit (no textual signal to key off), not rounded up to 100%. Full
`testthat` suite unchanged before/after (same 4 pre-existing unrelated
failures, 0 new).

A second, independent bug was found while building the harness: the
human-review CSVs (`generate_correction_files.R`, Section 13) were never
actually being written — the `write.csv()` calls were commented out while
the pipeline log unconditionally printed "Files saved." Also fixed in
v1.4.1.

## What's solid vs. what needs another pass

**Solid:** FCR test A (0/10,000 on parsed-truth values); Test B population
flag-rate gradient; format_no_colon/malformed_colon (100%);
field_misentry_sol/waso pre- and post-patch numbers; ampm_swap (0%
misrepair/miss); adjacent_swap_bed_sleep/awake_getup (100% on genuine
subset); compound_ampm_and_swap (0% misrepaired/missed, flagged rows
verified to reach the delivered dataset); the `generate_correction_files.R`
logging bug (root-caused, patched, reverified not to interfere with Step 6).

**Needs another pass:** Test B's per-population FAR_alter (NA-vs-altered
evaluator fix needed before quoting an exact number); L2 (type-correct)
tier not yet attempted, only L1 (any flag) and L3 (value-correct) exist;
cross_participant_spike detection not yet reverified at v3 rigor; the full
recall/specificity/PPV-curve, cluster-bootstrap, and multiverse phases from
`benchmark-design.md` have not been started.
