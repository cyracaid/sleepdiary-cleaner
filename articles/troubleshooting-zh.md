# 排错（中文）

[English
→](https://cyracaid.github.io/sleepdiary-cleaner/articles/troubleshooting.md)

找到你看到的那一行，往右读。

| 你看到的                                                                                                                                    | 原因                                                                                                                                                                                                                                                                                                                                                                                                                         | 怎么办                                                                                                                                                                                                                                                                       |
|---------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 找不到 `[NEW]manual_error_correction_review.csv`                                                                                            | \(1\) 你在 `output/` 里找；它在**项目文件夹**里。(2) 运行在 Step 5 之前就停了。(3) 你调用的是 [`run_setup()`](https://cyracaid.github.io/sleepdiary-cleaner/reference/run_setup.md)、[`run_report()`](https://cyracaid.github.io/sleepdiary-cleaner/reference/run_report.md) 或 [`run_visualization()`](https://cyracaid.github.io/sleepdiary-cleaner/reference/run_visualization.md)，它们不运行 Step 5。(4) 加载的是旧版本 | 在项目文件夹里运行 `list.files(pattern = "NEW", all.files = TRUE)`。看控制台是否走到了 `=== Step 5 ===`。检查 `getNamespaceVersion("sleepcleanr")`                                                                                                                           |
| Step 5 打印了 `Files saved`，但没有 `14. Saving review CSV files` 那一行                                                                    | 旧版本（1.4.0 及更早在这里并不写文件），或重装之后内存里仍加载着旧版本                                                                                                                                                                                                                                                                                                                                                       | 关掉所有 R 会话，重装，重启 R，检查 [`getNamespaceVersion()`](https://rdrr.io/r/base/ns-reflect.html)                                                                                                                                                                        |
| `No corrections file found () — skipping`                                                                                                   | 路径是有意清空的：这次只跑算法（`include_manual_corrections = FALSE`，即默认值），不是文件缺失                                                                                                                                                                                                                                                                                                                               | 用 `include_manual_corrections = TRUE` 重跑                                                                                                                                                                                                                                  |
| 同一个调用，升级前后结果不同                                                                                                                | `include_manual_corrections` 的默认值在 1.4.7 改变了                                                                                                                                                                                                                                                                                                                                                                         | 加上 `include_manual_corrections = TRUE` 来复现旧的完整运行                                                                                                                                                                                                                  |
| `Config file not found: my_study.yaml`                                                                                                      | 工作目录不是项目文件夹，或文件在别处                                                                                                                                                                                                                                                                                                                                                                                         | [`getwd()`](https://rdrr.io/r/base/getwd.html)；`list.files(pattern = "yaml$")`；写完整路径，或 [`setwd()`](https://rdrr.io/r/base/getwd.html) 到项目文件夹                                                                                                                  |
| `Cannot find your data file`                                                                                                                | YAML 里的数据路径不对，或文件不在 `project_dir` 里。相对路径是相对 `project_dir` 的。YAML 里写成 `paste0(dir, ...)` 的只是文字，不是 R 代码                                                                                                                                                                                                                                                                                  | 写普通路径                                                                                                                                                                                                                                                                   |
| `lazy-load database ... is corrupt`                                                                                                         | 包在一个正在运行的 R 会话里加载着，却被重装了                                                                                                                                                                                                                                                                                                                                                                                | 关掉所有 R 会话，重装，重启 R                                                                                                                                                                                                                                                |
| `there is no package called 'sleepdiary-cleaner'`                                                                                           | `sleepdiary-cleaner` 是仓库名，包名是 `sleepcleanr`                                                                                                                                                                                                                                                                                                                                                                          | `packageVersion("sleepcleanr")`                                                                                                                                                                                                                                              |
| `there is no package called 'remotes'`，或 `The project is out-of-sync -- use renv::status()`                                               | 你在本仓库的检出目录里运行 R，它用自己的 `renv` 库                                                                                                                                                                                                                                                                                                                                                                           | 先 `cd ~`，再 `Rscript --vanilla -e '...'`                                                                                                                                                                                                                                   |
| `Failed to install ... No commit found for the ref v1.x.y`                                                                                  | 那个 tag 不存在                                                                                                                                                                                                                                                                                                                                                                                                              | 到 releases 页面看现有的 tag                                                                                                                                                                                                                                                 |
| Step 5.75 的 `[VERIFY]` 行里显示的是文字而不是 id，例如 `pid= not format error ...`                                                         | `second_review_checklist.csv` 里有几行的 `pid` 或 `day_num` 列里是文字（例如一条备注在做文件时被拆到了几列里）。文件本身是合法的 CSV，但这些行无法确定是哪条记录                                                                                                                                                                                                                                                             | 运行会列出这些行在文件里的行号，把它们排除在外，并写到 `output/second_review_rows_skipped.csv`。请在清单里改正这些行。想让运行直接停下，设 `second_review.on_invalid_rows: stop`                                                                                             |
| `list.files(pattern = "[NEW")` 报错，或 `"[NEW]*"` 什么也找不到                                                                             | `pattern` 是正则表达式，`[NEW]` 是字符类                                                                                                                                                                                                                                                                                                                                                                                     | 用 `pattern = "NEW"` 或 `"\\[NEW\\]"`                                                                                                                                                                                                                                        |
| 加了修正之后，审核文件的行数还是一样                                                                                                        | 1.5.1 及更早版本里它列的是**修正之前**发现的错误。从 1.5.2 起 `[NEW]manual_error_correction_review.csv` 是状态表：看 `status_after_corrections`。`[NEW]manual_unusual_review.csv` 始终列出**所有** `unusual` 记录，每次运行都会重写，审核列为空；你的决定保存在你自己的 `manual_unusual_corrections.csv` 里，不在审核文件里                                                                                                  | 读 `status_after_corrections`。对 unusual 记录，请看你自己的 `manual_unusual_corrections.csv`，不要看 `[NEW]` 文件                                                                                                                                                           |
| `[NEW]manual_error_correction_review.csv` 里某行是 `in_manual_file_still_fails`，且 `category_after_corrections` 是 `error` 或 `skipped_na` | 这一行在你的人工错误文件里，但修正之后仍然不干净。`error`：顺序或合理性检查仍不通过。`skipped_na`：四个修正后的时间（bed、sleep、awake、getup）中仍缺一个，所以这一行不参加顺序检查。Step 6 日志里写着 “Undo correction” 的修正行会让这一行回到原始填写值，而原始值是错误的，所以仍是 `error`                                                                                                                                | 打开这一行，把四个修正后的时间和你的人工文件对照。补上缺失的时间或改正顺序，再重跑。各状态的含义见[状态表](https://cyracaid.github.io/sleepdiary-cleaner/articles/interpreting-output-zh.html#s-3)。这张表在 Step 8.5 之后才重写，所以更早停下的运行留下的是上一次运行的文件 |
| 运行停在 `7. Updating correction status...`，报 `Error: (converted from warning) Unknown or uninitialised column: manually_corrected`       | Step 7 要在你的人工错误修正文件上设置 `manually_corrected`，而文件里没有这一列。通常这只是警告；当 R 的 `warn` 选项为 2 时才变成错误，例如你的脚本或 `.Rprofile` 里有 `options(warn = 2)`（包本身不会设置它）。用 Excel 保存 CSV 可能丢掉或改名列，也可能改变格式                                                                                                                                                            | 在 CSV 里加一列 `manually_corrected`，全部填 `FALSE`，存成普通 CSV（UTF-8）再重跑。或者去掉 `options(warn = 2)`                                                                                                                                                              |
| `Parser already converted ... skipped manual override`，或 `Correction rows skipped: N`                                                     | 有人工睡眠指标时长修正没有被应用。默认情况下，如果解析器已经转换了 MM:SS 的值，以解析器为准                                                                                                                                                                                                                                                                                                                                  | 打开 `output/manual_corrections_not_applied.csv`，看每一行和原因。想让人工那行优先，在配置里设 `manual_corrections.manual_overrides_parser: true`                                                                                                                            |
| `remove.packages` 说没有这个包                                                                                                              | 那个库里没装过                                                                                                                                                                                                                                                                                                                                                                                                               | 忽略，直接安装                                                                                                                                                                                                                                                               |

如果都不是，把控制台里从 `=== SPL Sleep Pipeline` 到最后一个 `=== Step`
标题及其后面的输出、`getNamespaceVersion("sleepcleanr")`
的输出、项目文件夹里 `list.files(".", all.files = TRUE)`
的结果发出来。分享之前先去掉参与者 id。
