# Summary

Self-reported sleep diaries collected through ecological momentary assessment
(EMA) are chronically noisy at exactly the points that matter most: clock
times entered as free text carry AM/PM reversals, 12-hour dial habits,
order swaps between adjacent events, and duration values typed into
timestamp fields (and vice versa). Existing cleaning options sit at two
unhelpful extremes — fully automated scripts that silently "repair"
plausible-looking entries, and fully manual review of every record, which is
intractable at diary scale (a two-week, ~250-participant study produces
thousands of entries).

`sleepcleanr` is an R package implementing a hybrid cleaning pipeline for
morning sleep diaries. Deterministic, high-confidence rules (validated
operating points: a 3-hour adjacent-swap threshold and a 12-hour AM/PM flip)
correct only unambiguous ordering and format errors; every applied correction
is recorded with its type in the output data. Everything else —
value-level disagreements between self-reported durations and
timestamp-derived intervals, atypical-but-possible patterns, ambiguous
formats — is routed to structured human-review worksheets generated by the
pipeline itself (`[NEW]manual_error_correction_review.csv` and
`manual_unusual_review.csv`), which reviewers fill in and the next run
applies. The loop converges: corrected records stop reappearing, and the
run ends when the review worksheets return empty.

Three design commitments distinguish the pipeline. First, **no silent
repair**: a value is either left as reported, or changed with a recorded
correction type — the pipeline never reinterprets an entry without leaving a
trace (a field-misentry bug that silently misrepaired 96% of injected
clock-in-duration-field errors was found by synthetic benchmark and closed:
the current benchmark reports 0% silent misrepair). Second, **auditability**:
every run writes a per-step flag ledger tracking five independent evaluation
systems across the ten-stage pipeline, plus a correction status summary;
human-review files are applied only when the caller explicitly opts in
(`include_manual_corrections = TRUE`), so a dataset can never be modified by
leftover review files without the analyst's knowledge. Third,
**threshold transparency**: shipped thresholds are YAML-configurable
references validated on our data — not gospel — and the package ships an
operating-point sweep and Bland–Altman measurement-noise analysis showing how
detection thresholds relate to measurement noise.

# Statement of need

Sleep-diary cleaning sits between two communities with different tools.
Sleep researchers typically clean diaries by hand in spreadsheets —
unreproducible, unscalable, and unauditable — or with bespoke scripts that
are not shared and silently alter data. General-purpose data-cleaning
frameworks know nothing of diary semantics (that bedtime precedes sleep
onset precedes final awakening precedes get-up; that a 12-hour flip can
rescue a mis-entered AM/PM; that a zero-length sleep period is an error while
a zero-latency report is a benign diary habit). We know of no other R package
that implements diary-aware, human-in-the-loop cleaning with per-record
correction provenance, a convergence-guaranteed review cycle, and shipped
validation of its detection thresholds against both synthetic ground truth
and independent real data.

The package was developed for a real EMA sleep study (13,990 submissions,
237 participants, up to 15 diary days each) and validated on three tiers:
synthetic ground truth (4,736 injected errors, recall 0.995, 0% silent
misrepair), the real study data (controlled re-runs quantifying exactly what
human corrections contribute to the final dataset), and an independent,
externally published real-world dataset [@baigutanova2025hrv] — 49 healthy
adults' four-week sleep diaries (1,372 entries, 24-hour clock format, a
different schema with no separate get-up field) — which the pipeline
processed end-to-end without intervention, recovering the source study's
sleep metrics (mean total sleep time 7.55 h) and exposing two input-handling
defects that are fixed in the current version. Researchers collecting
longitudinal diary data with free-text time entries — in sleep, affect, or
any protocol where participants type clock times — should find the pipeline
directly usable: column mapping is configurable via YAML (or inferred via a
recorded, fail-loud guessing function), and a data-first entry point accepts
an in-memory data frame without any config file.
